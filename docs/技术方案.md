## 1. 目标与范围

### 1.1 必须交付（v1，对齐原版）

- 前置摄像头录制一段带表情的人脸，产出一个可保存、可回放的"脸"资产。
- 后置摄像头对准墙面、门板等竖直表面，点击放置，录好的脸从表面"顶"出来并回放表情。
- 墙面纹理在脸的轮廓周围被拉伸变形，看起来像脸从一层弹性膜后面顶出。
- 录屏分享。

### 1.2 增强交付（v2，原版做不到）

- 实时模式：前后摄像头同时工作，自己的脸实时从眼前的墙里顶出来，不需要先录制。
- 光照匹配：用场景光照估计给脸的贴图调色，让脸看起来像被墙面环境照亮。

### 1.3 不做

- Android、跨平台。
- 多张脸同时放置（架构上预留，v1 不做 UI）。
- 云端存储、社交分享以外的账号系统。

### 1.4 设备门槛

| 能力 | 最低设备 | 说明 |
|---|---|---|
| 两阶段模式（录制 → 放置） | iPhone X，iOS 13 | `ARFaceTrackingConfiguration` + `ARWorldTrackingConfiguration` 分时使用 |
| 实时模式 | A12 及以上，iOS 13 | `ARWorldTrackingConfiguration.userFaceTrackingEnabled` |

工程基线定在 iOS 16，Swift 5.9+，这样 `ARRaycastQuery`、`simd` 新 API、SwiftUI 导航都可以放心用。

## 2. 原版效果拆解

参考帧从原版演示视频抽取，含真人面部，不入库，本地放在 `docs/reference/`。

| 阶段 | 画面特征 | 对应技术 |
|---|---|---|
| 录制页 | 上半：3D 人脸网格，表面贴着实时投影上去的脸。下半：前置摄像头原始画面。 | 人脸网格 + 相机投影纹理预览 |
| Face Review | "Start Playback" 预览，缩略图，分享，"Make your face" 主按钮 | 资产回放预览 |
| 砖墙放置 | 脸从砖墙挤出，砖缝线条绕脸轮廓弯曲，侧看时砖纹"盖"在脸颊上 | 挤出网格 + 屏幕空间折射采样 + 径向 mask 过渡 |
| 木门放置 | 脸在木门上眨眼、咧嘴，木纹在脸周围被拉伸 | 顶点动画回放 + 折射 |

三个关键结论：

1. **"标准人脸白膜"就是 ARKit 的 canonical face mesh。** 拓扑固定，1220 个顶点，2304 个三角形，带固定展开 UV。
2. **脸的贴图不是直接把视频贴上去。** canonical UV 和相机画面没有对应关系，必须把顶点投影到相机图像里取样。
3. **墙面变形是屏幕空间采样。** 木纹线条弯曲是折射类 shader 的典型特征，不可能靠普通贴图做出来。

```
│ FaceRecorder        │─── 写入 ───▶ │ FaceRecording (.faceplant 包) │
│  MeshStreamWriter   │              │  manifest.json         │
│  AVAssetWriter(HEVC)│              │  mesh.bin · texture.mov│
└─────────────────────┘              └────────────────────────┘
```

设计原则：

- **渲染层只认协议。** `FaceRenderer` 只消费 `FaceMeshSource` 和 `CameraTextureProvider`，不关心数据来自实时追踪还是录制文件。实时模式和回放模式共用同一套 shader。
- **数据模型全部是值类型。** 每一帧网格是一个 `struct FaceMeshFrame`，录制包是 `struct FaceRecording`。只有 session、renderer、writer 这类持有系统资源的对象用 class。
- **ARSession 只有一个持有者。** 配置切换集中在 `ARSessionController`，UI 不直接碰 `ARSession`。

## 4. 关键技术点

### 4.1 人脸网格与坐标系

数据来源：`ARFaceAnchor.geometry`，类型 `ARFaceGeometry`。

| 属性 | 类型 | 说明 |
|---|---|---|
| `vertices` | `[SIMD3<Float>]` | 1220 个，单位米，face anchor 局部坐标，每帧变化 |
| `textureCoordinates` | `[SIMD2<Float>]` | 1220 个，固定不变，canonical 展开 UV |
| `triangleIndices` | `[Int16]` | 2304 × 3，固定不变 |
| `ARFaceAnchor.blendShapes` | `[BlendShapeLocation: NSNumber]` | 52 个系数，v1 顺手录下来，暂不用 |

坐标系：原点在头部中心靠近鼻后，+y 向上，+z 从脸朝向相机。脸的表面大致在 z ∈ [+0.03, +0.08] m，脸颊两侧、额头边缘接近 z = 0 甚至为负。

这个分布对放置效果非常关键：**把 anchor 原点放在墙面上，脸自然就突出墙面 3 到 8 厘米**，不需要额外挤出逻辑，只需要把 z < 0 的部分裁掉。见 4.6。

`triangleIndices` 和 `textureCoordinates` 是固定的，启动时取一次缓存即可，每帧只上传 `vertices`。

### 4.2 相机画面投影到网格

目的：对每个顶点算出它在 `ARFrame.capturedImage` 里的归一化坐标，作为采样 UV。

```
clip   = P · V · M · float4(v, 1)
ndc    = clip.xy / clip.w                       // [-1, 1]
uvView = ndc * float2(0.5, -0.5) + 0.5          // 视口归一化坐标，y 向下
uvImg  = displayTransform⁻¹ · uvView            // capturedImage 归一化坐标
```

| 符号 | 来源 |
|---|---|
| `M` | `ARFaceAnchor.transform` |
| `V` | `ARCamera.viewMatrix(for: orientation)` |
| `P` | `ARCamera.projectionMatrix(for: orientation, viewportSize:, zNear:, zFar:)` |
| `displayTransform` | `ARFrame.displayTransform(for: orientation, viewportSize:)` |

两个坑：

1. **`displayTransform` 的方向。** 它把 capturedImage 归一化坐标映射到视口归一化坐标，所以这里要用逆矩阵。前置摄像头的"自拍镜像"也包含在这个变换里，不要自己再翻转一次。
2. **`orientation` 和 `viewportSize` 必须和实际渲染一致。** 录制阶段锁竖屏，`viewportSize` 用 Metal drawable 尺寸，三处保持同一组参数。

这一步放在顶点着色器里做，每帧只需要传 `P·V·M` 和 `displayTransform⁻¹`（3×3 齐次矩阵即可）。

### 4.3 烘焙展开贴图

目的：把每一帧的相机画面按 canonical UV 展开成一张正方形贴图，录制时存成视频，回放时直接贴在网格上，不再依赖相机参数。

Metal 离屏 pass：

- 顶点着色器：位置 = `float4(uv.x * 2 - 1, 1 - uv.y * 2, 0, 1)`，也就是把 UV 当裁剪空间坐标。同时按 4.2 算出 `uvImg` 作为 varying。
- 片元着色器：用 `uvImg` 采样 capturedImage 的 Y 和 CbCr 两张纹理，转 RGB 输出。
- 渲染目标：`MTLTexture`，1024 × 1024，`bgra8Unorm`，`usage = [.renderTarget, .shaderRead]`。

需要处理的细节：

| 问题 | 处理 |
|---|---|
| UV 岛边缘采样时出现黑边 | 烘焙后跑一遍 2 到 4 像素的 dilation pass，或者在回放 shader 里把 mask 收窄到岛内 |
| 顶点被头发、手遮挡 | v1 不处理。v2 可用 `ARFrame.segmentationBuffer` 或 `ARFaceAnchor.isTracked` 做质量判断 |
| 前置摄像头 YCbCr 色彩 | 用 BT.601 全范围矩阵，和 Apple Metal 示例一致 |

烘焙结果同时用于录制页的实时预览，这正是原版录制页上半部分看到的东西。

**M0 结论（2026-11-04，iPhone 16，iOS 26，视口 393×852）**

- 4.2 的投影公式与 `displayTransform` 逆变换验证通过：烘焙贴图回贴到实时人脸网格上，眼、鼻、嘴与真人完全对齐，无镜像。
- canonical UV 方向约定：`flipV = false`，即 v = 0 落在纹理顶部，直接按 Metal 的左上角原点写入，展开贴图就是正立的脸。后续 Metal 渲染器沿用这个约定，`BakeUniforms.flipV` 字段可以删除。
- SceneKit 显示 `MTLTexture` 不需要额外的 `contentsTransform` 翻转。
- 两个待 M1 处理的观察：
  - 烘焙目标用 `bgra8Unorm` 时，SceneKit 把 sRGB 编码值当线性值采样，贴图区域比真人略亮。自家 Metal 管线里烘焙与采样约定一致即可消除；若仍要给 SceneKit 或 `UIImage` 消费，改用 `bgra8Unorm_srgb` 目标并在 shader 里输出线性值。
  - 头部侧转时被遮挡的半边脸出现拉伸涂抹，属于掠射角投影的固有现象。录制阶段用 `ARFaceAnchor.transform` 的朝向角做质量过滤，或者多帧融合，都放到 v2。

### 4.4 录制数据格式

一个录制是一个目录包 `<uuid>.faceplant`，存在 `Application Support/Recordings/`：

```
<uuid>.faceplant/
├── manifest.json
├── topology.bin     canonical UV 与索引，回放不依赖 ARKit 会话
├── mesh.bin
├── texture.mov
└── thumbnail.jpg
```

**topology.bin**，小端：

```
magic 'FPTP' UInt32 · version UInt32 · vertexCount UInt32 · indexCount UInt32
uv      Float32 × 2 × vertexCount
indices Int16 × indexCount
```

**manifest.json**（M1 实现：`FaceRecordingManifest`，ISO 8601 日期）

```json
{
  "formatVersion": 1,
  "createdAt": "2026-11-03T14:05:00Z",
  "duration": 12.433,
  "vertexCount": 1220,
  "meshFrameCount": 373,
  "textureSize": 1024,
  "hasBlendShapes": true,
  "deviceModel": "iPhone16,1"
}
```

**mesh.bin**，小端，固定布局：

```
Header (32 bytes)
  magic        UInt32   'FPMS'
  version      UInt32   1
  vertexCount  UInt32   1220
  frameCount   UInt32
  flags        UInt32   bit0 = float16 顶点, bit1 = 含 blendShapes, bit2 = 含左右眼球变换
  reserved     12 bytes

Frame × frameCount
  timestamp    Float64  相对录制起点的秒数
  vertices     vertexCount × 3 × (Float16 | Float32)
  blendShapes  52 × Float32   (flags.bit1 时存在，顺序固定为 BlendShapeLocation 的字典序)
  eyes         2 × 16 × Float32 (flags.bit2 时存在，左眼在前，列主序 4x4，见 4.8)
```

新字段只通过 flags 追加在帧尾，旧文件没有对应 bit 时 Reader 直接跳过，不需要升版本号。

Float16 足够：人脸尺寸 0.2 m 量级，Float16 在这个范围的精度约 0.0001 m。30 fps 下每秒约 220 KB，12 秒录制不到 3 MB。

**texture.mov**：`AVAssetWriter`，`AVVideoCodecType.hevc`，1024 × 1024，30 fps，通过 `AVAssetWriterInputPixelBufferAdaptor` 写入。像素缓冲从 adaptor 的 pool 取，烘焙 pass 用 `CVMetalTextureCache` 直接把 pool 里的 `CVPixelBuffer` 包成 `MTLTexture` 当 render target，避免一次拷贝。

**时间同步**：mesh 帧和视频帧都用 `ARFrame.timestamp - startTimestamp` 作为时间戳，视频帧的 presentation time 用同一个值。回放时以视频时钟为主，mesh 帧按时间戳二分查找并做线性插值。

**音频**：v1 不录。架构上给 `AVAssetWriter` 预留一个 audio input，v2 决定。

### 4.5 放置与回放

**会话配置**

```swift
let config = ARWorldTrackingConfiguration()
config.planeDetection = [.vertical]
config.environmentTexturing = .none
```

**放置**：用户点击屏幕，点击位置先经 `displayTransform` 的逆变换换算成 capturedImage 归一化坐标，再用 `ARFrame.raycastQuery(from:allowing: .estimatedPlane, alignment: .any)` 构造查询，调用 `session.raycast(_:)`。先用 `.estimatedPlane` 保证响应快，结果里带 `ARPlaneAnchor` 的优先。M2 实现：`FacePlacement`、`PlaceViewController`。

**朝向对齐**：脸的 +z 要对准墙面法线朝外，+y 对准世界上方：

```
forward = 墙面法线（世界坐标，朝外）
up      = normalize((0,1,0) - dot((0,1,0), forward) · forward)
right   = cross(up, forward)
M_face  = [right, up, forward, hitPosition]
```

法线取 raycast 结果 `worldTransform` 的 +y，若背向相机则取反。水平表面（桌面、地面）上世界上方与法线平行，改用"远离观察者"的方向做脸的 +y，站在近侧低头看脸是正的。

把这个变换挂成一个 `ARAnchor` 加入 session，渲染时每帧从 `ARFrame.anchors` 里按 identifier 取最新的 transform，这样世界追踪的漂移修正会自动应用到脸上。再次点击先移除旧 anchor 再加新的。

**回放**：`FaceRecordingPlayer` 持有一个 `CADisplayLink` 驱动的时钟，循环播放：

- 视频帧：`AVPlayerItemVideoOutput.copyPixelBuffer(forItemTime:itemTimeForDisplay:)`，用 `CVMetalTextureCache` 包成 `MTLTexture`。
- mesh 帧：按时钟时间二分查找前后两帧，顶点线性插值，写入当前帧的顶点缓冲。

`FaceRecordingPlayer` 对外实现 `FaceMeshSource` 协议，渲染层不知道它在回放。

### 4.6 挤出与墙纹拉伸 shader

这是整个 app 的灵魂。M2 第一版只在脸网格内部按 canonical UV 半径做遮罩，真机上脸只剩中间一小块，网格外面什么都没有；对照原版木门截图，被推开的墙纹范围约是脸的两倍，说明拉伸发生在脸周围的一整块墙面上。M2 第二版改成下面的结构。

**凸出深度**：对照原版砖墙视频的侧视图，脸是整个伸出墙面的，两侧不是被切平，而是被墙纹"包"住。ARKit 网格从鼻尖到发际线、下巴底、耳侧有 6 到 8 cm 深，比原版的面具深得多：按"鼻尖离墙 5 cm"摆会切掉额头和下巴，把脸往墙里按也一样，而且贴近墙面的部分随表情前后晃动、切边来回跳会闪（真机确认）。所以默认不切：渲染器按第一帧外轮廓最靠后的 z 算整体偏移，让轮廓最低点离墙 `rimClearance`（5 mm），再把深度整体压到 `depthScale` = 0.6，鼻尖离墙约 5 cm、额头和下巴离墙 1 到 2 cm，鼓包把轮廓到墙面全部包住。`sinkDepth` 保留给想把脸按进墙里的情况，默认 0。

**遮罩**：按顶点到外轮廓的测地距离 `rim`（米，`FaceMeshRim`，静止姿态算一次）做等宽淡出带：`mask = smoothstep(0, fade, rim)`。淡出带各向异性：额头、下巴方向宽 `edgeFade`，两侧宽 `edgeFade × sideFade`，按局部 xy 相对脸中心的方向插值。两侧要宽是因为烘焙贴图贴近耳朵的部分带着录制时的背景（白墙、窗户）；上下要窄是因为额头、下巴本来就是脸，切多了脸显得小。用包围盒椭圆做遮罩时额角和下颌会被切掉一大块，所以换成测地距离。

**拉伸坐标**：在脸局部 xy 平面上用椭圆归一化距离 `d = |(xy − faceCenter) / faceRadius|`。`faceCenter`、`faceRadius` 从第一帧墙前（嵌入后 z' > 0）顶点的包围盒取，`d = 1` 大致就是脸的轮廓。

**橡皮膜拉伸**：墙纹采样点往脸中心拉：

```
w(d)  = 1 − smoothstep(1, warpOuter, d)          // 脸内全力，到 warpOuter 衰减为 0
rest  = faceCenter + (xy − faceCenter) · (1 − warpStrength · w(d))
wall  = sampleCamera(project(rest, z = 0))       // rest 投影到 capturedImage 再采样
```

显示在 `xy` 的墙纹来自更靠近脸中心的 `rest`，视觉上就是墙纹被脸向外推开；`warpOuter` 之外采样点等于自身，和背景无缝。

**两个 pass 共用这个函数**

1. 墙面补丁 pass（`wallVertex` / `wallFragment`）：一块贴在墙上（z = −1 mm）、围着脸的平面，每个片元按上面的公式采墙纹，`d ≥ warpOuter` 直接 discard。
2. 脸 pass（`faceVertex` / `faceFragment`）：顶点先做 `z' = z · depthScale + depthOffset`，`z' < 0` 的片元被墙面切掉。`rim ≥ edgeFade` 完整显示烘焙贴图；淡出带里过渡到按同一公式采的墙纹，再叠一点视空间法线驱动的折射，让起伏处的墙纹跟着弯。脸的淡出带、裙边和补丁用同一个 `rest`，交界处连续。

**鼓包**：ARKit 的网格是一张开口薄壳，边缘悬在墙面上方，低角度看就是空心面具。原版像一张橡皮墙被后面的脸顶起来，脸四周到墙面是一个平滑的鼓包，墙纹沿着鼓包弯过去。`FaceSkirt` 为外轮廓环上的每个顶点向外生成 6 圈顶点：第 t 圈沿远离脸中心的方向外推 `高度 × skirtSlope × t`，高度按 (1 − t)² 从轮廓高度衰减到 0，相邻圈连成四边形带。第一版做的 45° 单层斜坡在额头处像一堵围墙，第二版的余弦轮廓在轮廓处有一段平台、看起来像先鼓出去再掉下来，所以改成从轮廓就开始下落的二次曲线。鼓包顶点复用轮廓顶点的 UV，`rim` 取负值，和脸一起走脸 pass，遮罩为零，显示拉伸后的墙纹，与补丁连续。鼓包随 depthScale / sinkDepth 变，每帧在 CPU 上重算，1223 + 约 700 个顶点可以忽略。

绘制顺序：背景 → 补丁 → 脸（含鼓包），补丁和脸都做深度测试并写深度，脸在 z ≥ 0 自然盖住补丁。

参数初值（`FaceRenderParameters.standard`，两页的"调参"面板可实时改：滑杆加 − / + 按钮，每次变动显示值的 0.1，米制参数按厘米显示；调好后回填）：

| 参数 | 初值 | 作用 |
|---|---|---|
| `edgeFade` | 0.02 | 额头、下巴方向的淡出带宽度（米） |
| `sideFade` | 2 | 两侧淡出带是上下的倍数 |
| `warpStrength` | 0.3 | 采样点往脸中心拉的比例，决定墙纹被推开多少 |
| `warpOuter` | 2.0 | 拉伸衰减到零的 d，决定被推开的范围 |
| `refractStrength` | 0.01 | 过渡带里叠加的法线折射偏移 |
| `depthScale` | 0.6 | 顶点 z 的缩放；ARKit 网格比原版面具深，压扁后整张脸都在墙前 |
| `sinkDepth` | 0 | 把脸往墙里按的深度（米），0 时整个轮廓都在墙前；按进去的切边随表情晃动会闪，一般不用 |
| `rimClearance` | 0.005 | sinkDepth 为 0 时外轮廓最低点离墙的距离（米），整张脸抬高或贴近 |
| `skirtSlope` | 2.5 | 鼓包宽度与轮廓高度之比，越大越平缓 |
| `faceBrightness` | 1 | 烘焙贴图整体亮度 |
| `wallTileSize` | 1 | 录制页预览墙一张贴图铺多大（米），AR 场景不用 |

要点：

- **墙纹采样的是 capturedImage，不是帧缓冲。** 脸和补丁所在的像素本来就是墙，直接采相机纹理即可，不需要 grab pass 或额外的 texture copy。
- **`discard` 切平面** 处理网格穿到墙后的部分；鼓包处理网格边缘悬在墙前的部分。两者配合，脸和墙之间没有缝。
- 采样 `rest` 时要重新投影（一次 4x4 乘法），不能直接用片元的屏幕坐标加偏移，否则视角一变拉伸就不跟墙走。
- 深度测试开启，写深度，这样之后放多张脸时相互遮挡正确。

**法线**：按面累加再归一化。M2 实现放在 CPU（`FaceMeshNormals`），1223 顶点、2400 多个三角形每帧只要几十微秒，不值得上 compute kernel。

### 4.7 实时模式：前后摄像头同开

```swift
guard ARWorldTrackingConfiguration.supportsUserFaceTracking else { /* 退回两阶段 */ }
let config = ARWorldTrackingConfiguration()
config.planeDetection = [.vertical]
config.userFaceTrackingEnabled = true
```

这个配置下后置摄像头是主画面，`ARFaceAnchor` 来自前置摄像头并通过同一个 delegate 回调送达。我们只取它的 `geometry`，不用它的 `transform`。

数据流：`LiveFaceMeshSource` 每帧从 `ARFaceAnchor` 拿顶点，`FaceTextureBaker` 用 **前置摄像头的图像** 烘焙贴图。注意：这个模式下 `ARFrame.capturedImage` 是后置画面，前置画面没有直接暴露。

**M0 结论（2026-11-04，iPhone 16）**

- `supportsUserFaceTracking` 为真，`ARFaceAnchor` 在世界追踪会话里正常送达，`isTracked` 与 blendShapes 都有值，悬浮网格跟随表情。
- 再开一路前置 `AVCaptureSession` 的方案 **不可行**：探针确实收到了前置帧，但它一启动就接管了前置摄像头并改写 active format，ARKit 随即报 `ARErrorCodeSensorFailed (102)`，底层是 `AVFoundationErrorDomain -11873`，整个会话失败。同一颗摄像头只能有一个 capture 客户端，这是 AVFoundation 的模型限制，不是设备问题。
- 探针并发期间还出现了 `World tracking performance is being affected by resource constraints`，说明即便能共存，三路相机输入的资源也吃不消。

因此实时模式确定按下面的方案走：

**实时模式 = 实时顶点 + 按表情检索的录制贴图。**

1. 用户先用两阶段流程录一段脸，这一步不可省略。录制包里的每一帧贴图都带有当帧的 52 个 blendShape 系数（4.4 的 `mesh.bin` 已经预留）。
2. 实时模式下顶点来自当前 `ARFaceAnchor`，贴图不烘焙，而是拿当前帧的 blendShape 向量在录制包里做最近邻检索，取系数距离最小的那一帧贴图。
3. 检索成本是 52 维向量对几百帧做一次距离计算，每帧微秒级。为了避免贴图在相邻帧之间抖动，加一个滞后阈值：只有新候选比当前帧好出一个 margin 才切换。
4. 视频帧随机访问走 `AVAssetReader` 预解码到一个 `MTLTexture` 数组，1024² BGRA 每帧 4 MB，300 帧 1.2 GB 太大；降到 512² 并只缓存按 blendShape 聚类后的代表帧（例如 32 帧 32 MB）即可。

效果上，嘴张开时能检索到嘴张开的贴图，比静态贴图自然得多，录制时引导用户做几个夸张表情就能覆盖常见状态。`ARFrame.capturedImage` 在这个模式下是后置画面，正好直接喂给 4.6 的折射采样。

### 4.8 洞口加盖与假眼球

ARKit 标准网格在两只眼睛和嘴的内侧没有三角形，烘焙贴图和回放都会在那里留下黑洞（M1 真机截图已确认）。原版的录制截图里张嘴能看到舌头贴在一个平面上，眼睛是视频里的真眼睛，整张脸没有洞，说明原版用的是封闭的面具模型。

**加盖**（`FaceMeshCapping`，默认开启）

- 从索引里找只属于一个三角形的边，按原三角形的方向串成环。ARKit 网格会得到四个环：最长的是脸的外轮廓，其余是左眼、右眼、嘴。
- 每个洞在中心加一个顶点，扇形三角化。中心顶点的位置和 UV 取环上顶点的平均，每帧随表情一起动；盖子三角形沿 b→a 绕向，与相邻原三角形保持一致。顶点数 1220 变 1223。
- 加盖只发生在内存里：`topology.bin` 与 `mesh.bin` 存 ARKit 原始数据，加载后再加盖，旧录制包直接受益。
- 盖子和原网格一起进烘焙 pass。UV 空间里洞的位置本来就是空的，盖子正好填进去，张嘴时舌头、牙就贴在盖子上。M2 的 Metal pass 只是多几十个索引，折射与切平面逻辑不变。

如果真机对比后觉得面具感不够，或者想起原版有耳朵、脖子这类 ARKit 网格没有的部位，再换成带 52 个 ARKit blendShape 的独立面具模型：录制包已经存了系数，顶点改为"基础模型 + 系数 × 位移"计算，其余管线不变。

**假眼球**（`FaceRenderOptions.showsEyeballs`，默认关闭）

加盖后眼睛直接显示视频里的真眼睛，正常回放不需要假眼球。它的价值在 v2 实时模式：贴图按表情检索，视线与当下不一致时，用假眼球跟随实时视线。

- 数据来源：`ARFaceAnchor.leftEyeTransform` / `rightEyeTransform`（iOS 12+），face 局部坐标下的刚体变换，原点在眼球中心，+z 是视线方向。录制时和顶点一起写进 `mesh.bin`（flags.bit2），回放时平移线性插值、旋转 slerp。
- 几何：每只眼一个球，半径取真人眼球的 11.5 mm（`EyeballStyle.radius`）。
- 外观：不用美术资源，瞳孔、虹膜、巩膜按与视线方向的夹角分带。SceneKit 用一张经纬展开贴图（`EyeballStyle.makeTextureImage`），球绕 x 轴转 90° 让极点对准 +z（`EyeballNode`）；M2 Metal 在 fragment 里直接用模型空间法线算。
- 开启时眼睛的盖子会挡住眼球，需要同时去掉眼睛两个环的盖子，这是 v2 的事。

## 5. 渲染管线

基于 Apple 的 "Displaying an AR Experience with Metal" 示例骨架，`MTKView` 驱动，每帧：

```
1. 取 ARFrame，更新相机 Y/CbCr 纹理（CVMetalTextureCache）
2. BackgroundPass：全屏三角形画 capturedImage，用 displayTransform
3. 若 FaceMeshSource 有新帧：
   3a. 上传顶点缓冲（triple buffering，避免 CPU/GPU 争用）
   3b. CPU 重算法线，上传法线缓冲
   3c. 录制模式：BakePass 烘焙贴图 → 写入 AVAssetWriter
4. FacePass：挤出 + 折射，深度测试开
5. present
```

M2 实现：`FaceplantRenderer` 一个类承担 2 与 4 两个 pass，共用一个 render command encoder。相机帧直接读 `session.currentFrame`，不经 delegate；相机 Y/CbCr 纹理由 command buffer 的 completed handler 持有到 GPU 读完。录制页上半的实时预览（`WallPreviewView`）走同一个渲染器的 `.still` 场景：墙是 z = 0 平面上按 1 m 一张镜像平铺的贴图（默认程序生成的砖墙 `BrickTexture`，可换相册照片），由补丁 pass 整面画出来，墙纹不走投影而是直接按脸局部 xy 取样；脸固定在原点，环绕相机（`OrbitCamera`）单指拖动转角度、双指捏合拉远拉近、双击复位，能看侧面。下半的前置画面仍用 SceneKit 叠网格。调参面板两页共用，不用录一段再去墙上看。

缓冲策略：顶点、法线、uniform 各三份，`DispatchSemaphore(value: 3)` 控制在途帧数。

ARSession 的 delegate 队列不要用主线程。M0 里 delegate 跑在主线程，SceneKit 渲染一忙就出现 `The delegate of ARSession is retaining N ARFrames` 警告，这是回调积压而不是泄漏。M1 起设置 `session.delegateQueue` 为独立串行队列，烘焙与录制写入都在该队列完成，只有 UI 状态回主线程。

录制页上半的预览用同一套 `FacePass`，只是 `M` 用 face anchor transform，`mask = 1`，`refractStrength = 0`，等价于只显示烘焙贴图。

```swift
/// 一帧人脸网格。顶点在 face 局部坐标，单位米。
struct FaceMeshFrame: Sendable {
    var timestamp: TimeInterval
    var vertices: [SIMD3<Float>]
    var blendShapes: [Float]?   // 52 个，顺序见 BlendShapeOrder
}

/// 渲染层的唯一网格入口。实时追踪和录制回放都实现它。
protocol FaceMeshSource: AnyObject {
    var topology: FaceMeshTopology { get }
    /// 返回当前应渲染的帧；nil 表示本帧没有新数据，渲染层沿用上一帧。
    func currentFrame(at hostTime: TimeInterval) -> FaceMeshFrame?
    /// 脸的贴图。实时模式下由 baker 每帧更新，回放模式下由 player 更新。
    var faceTexture: MTLTexture? { get }
}

/// 渲染层的相机纹理入口。
protocol CameraTextureProvider: AnyObject {
```

错误处理：所有 I/O 和 Metal 资源创建走 `throws`，统一到 `enum FaceplantError: Error`。不允许 `try!`，不允许静默吞错。

## 8. 风险、验收点与合规

| 风险 | 影响 | 应对 |
|---|---|---|
| `displayTransform` 方向、镜像搞错 | 贴图整体错位 | M0 已在 iPhone 16 上验收通过 |
| 烘焙贴图 UV 岛接缝 | 脸边缘有黑线 | dilation pass；mask 外圈本来就过渡到墙面，接缝大多被盖住 |
| 回放时间漂移 | 嘴型和贴图不同步 | 视频时钟为主，mesh 跟随；每帧都写时间戳而不是假设固定 fps |
| 竖直平面检测慢 | 用户点了没反应 | raycast 先用 `.estimatedPlane`，后台持续检测，命中后再纠正法线 |
| 实时模式拿不到前置画面 | v2 形态受限 | M0 已确认不可行，实时模式按 4.7 的表情检索方案 |
| 墙面纹理单一时折射不明显 | 效果平淡 | 不是技术问题，产品层面引导用户选有纹理的表面 |

合规：

- `NSCameraUsageDescription` 必填，文案说明用于人脸录制与 AR 放置。
- App Store 审核指南对 TrueDepth 面部数据有明确限制：录制的网格和贴图只能用于用户主动创建的内容，不得上传做任何分析或广告用途。v1 全部本地存储，分享只走用户主动触发的录屏导出。
- 录制包放在 `Application Support`，标记 `isExcludedFromBackup = false` 让用户数据可随 iCloud 备份，但不做任何自动上传。

## 9. 附录：Shader 草案

> 方案阶段的草案，M2 实现以 `Faceplant/Rendering/Shaders.metal` 为准，脸 pass 的遮罩与拉伸已按 4.6 第二版改写。

```metal
#include <metal_stdlib>
#include "ShaderTypes.h"
using namespace metal;

// ---------- 公共 ----------

constexpr sampler linearClamp(mag_filter::linear, min_filter::linear, address::clamp_to_edge);

// BT.601 全范围 YCbCr -> RGB，与 Apple ARKit Metal 示例一致
inline float3 ycbcrToRGB(float y, float2 cbcr) {
    const float4x4 m = float4x4(
        float4( 1.0000f,  1.0000f,  1.0000f, 0.0f),
        float4( 0.0000f, -0.3441f,  1.7720f, 0.0f),
        float4( 1.4020f, -0.7141f,  0.0000f, 0.0f),
        float4(-0.7010f,  0.5291f, -0.8860f, 1.0f));
    return (m * float4(y, cbcr, 1.0f)).rgb;
}

inline float3 sampleCamera(texture2d<float> luma, texture2d<float> chroma, float2 uv) {
    float  y    = luma.sample(linearClamp, uv).r;
    float2 cbcr = chroma.sample(linearClamp, uv).rg;
    return ycbcrToRGB(y, cbcr);
}

// ---------- 烘焙 pass：把相机画面展开到 canonical UV ----------

struct BakeVertexOut {
    float4 position [[position]];
    float2 cameraUV;
};

vertex BakeVertexOut bakeVertex(uint vid [[vertex_id]],
                                const device float3*  vertices [[buffer(0)]],
                                const device float2*  uvs      [[buffer(1)]],
                                constant BakeUniforms& u       [[buffer(2)]]) {
    float2 uv = uvs[vid];
    float4 clip = u.projectionViewModel * float4(vertices[vid], 1.0f);
    float2 ndc  = clip.xy / clip.w;
    float2 uvView = ndc * float2(0.5f, -0.5f) + 0.5f;
    float3 uvImg  = u.displayTransformInverse * float3(uvView, 1.0f);

    BakeVertexOut out;
    out.position = float4(uv.x * 2.0f - 1.0f, 1.0f - uv.y * 2.0f, 0.0f, 1.0f);
    out.cameraUV = uvImg.xy;
    return out;
}

fragment float4 bakeFragment(BakeVertexOut in [[stage_in]],
                             texture2d<float> luma   [[texture(0)]],
                             texture2d<float> chroma [[texture(1)]]) {
    return float4(sampleCamera(luma, chroma, in.cameraUV), 1.0f);
}

// ---------- 脸 pass：挤出 + 折射 ----------

struct FaceVertexOut {
    float4 position [[position]];
    float2 uv;
    float3 normalView;
    float  localZ;
};

vertex FaceVertexOut faceVertex(uint vid [[vertex_id]],
                                const device float3*  vertices [[buffer(0)]],
                                const device float2*  uvs      [[buffer(1)]],
                                const device float3*  normals  [[buffer(2)]],
                                constant FaceUniforms& u       [[buffer(3)]]) {
    float3 v = vertices[vid];
    FaceVertexOut out;
    out.position   = u.projectionViewModel * float4(v, 1.0f);
    out.uv         = uvs[vid];
    out.normalView = normalize((u.viewModel * float4(normals[vid], 0.0f)).xyz);
    out.localZ     = v.z;
    return out;
}

fragment float4 faceFragment(FaceVertexOut in [[stage_in]],
                             texture2d<float> faceTex [[texture(0)]],
                             texture2d<float> luma    [[texture(1)]],
                             texture2d<float> chroma  [[texture(2)]],
                             constant FaceUniforms& u [[buffer(0)]]) {
    // 墙面作为切平面，墙后的网格不画
    if (in.localZ < 0.0f) discard_fragment();

    // 屏幕归一化坐标 -> capturedImage 坐标
    float2 screenUV = in.position.xy / u.viewportSize;
    float2 offset   = in.normalView.xy * (u.refractStrength + in.localZ * u.stretchStrength);
    float3 uvImg    = u.displayTransformInverse * float3(screenUV + offset, 1.0f);
    float3 wall     = sampleCamera(luma, chroma, uvImg.xy);

    float3 face = faceTex.sample(linearClamp, in.uv).rgb;
    // 光照匹配：v2 用 ARFrame.lightEstimate 填 u.faceTint
    face *= u.faceTint;

    float d    = distance(in.uv, u.faceCenterUV);
    float mask = 1.0f - smoothstep(u.maskInner, u.maskOuter, d);

    return float4(mix(wall, face, mask), 1.0f);
}
```

`ShaderTypes.h` 中的 uniform 布局用 C struct 定义，Swift 侧通过 bridging header 共享，避免手工对齐偏移：

```c
typedef struct {
    matrix_float4x4 projectionViewModel;
    matrix_float3x3 displayTransformInverse;
} BakeUniforms;

typedef struct {
    matrix_float4x4 projectionViewModel;
    matrix_float4x4 viewModel;
    matrix_float3x3 displayTransformInverse;
    vector_float2   viewportSize;
    vector_float2   faceCenterUV;
    vector_float3   faceTint;
    float           maskInner;
    float           maskOuter;
    float           refractStrength;
    float           stretchStrength;
} FaceUniforms;
```
